> **Disclosure:** this guide has no affiliate links today. If we add any later (for example to server providers), they'll be marked here, and we recommend the same options whether or not they pay us.

Zapier charges by the task. When we checked in late 2026, its Professional plan was $19.99 a month (billed yearly) for 750 tasks, and busy automations cost more ([Zapier's own pricing explainer](https://zapier.com/blog/zapier-pricing/)). [n8n](https://n8n.io) does the same job: "when a form is filled in, add the lead to a spreadsheet and send me a message". On your own server, you pay for the server, not for each run.

**Before you switch, the honest trade-offs:**

- **n8n is more technical than Zapier.** The editor is visual, but you'll meet terms like JSON and webhooks sooner. Expect an afternoon of learning.
- **Fewer ready-made connections.** n8n has hundreds of built-in integrations, which is fewer than Zapier. It also has a generic HTTP Request node that can talk to almost any service with an API.
- **License:** n8n is "fair-code" under its [Sustainable Use License](https://docs.n8n.io/n8n-community-license). It allows use "for your own internal business purposes", so running your own business's automations is free. Offering n8n to your customers, for example letting them log in and build their own workflows, needs a commercial agreement with n8n.
- **You run it.** If the server is down, your automations don't run. Add it to [Uptime Kuma](./02-uptime-kuma.md) and set up [backups](./08-backups.md).

**You need:** a server with Docker ([30-minute setup guide](./01-the-7-dollar-server.md)), the [one-Caddy setup](./07-caddy.md) with its `web` network, and a DNS A record such as `automate` pointing at the server.

**Memory:** n8n used about 750 MB in our test, plus a little for Postgres. Use a 2 GB server if it runs alone, or 4 GB alongside other apps ([Which VPS?](./09-which-vps.md)).

Time: about 15 minutes. Extra cost: $0.

## 1. Folder and settings

```bash
mkdir -p ~/apps/n8n/data && cd ~/apps/n8n
sudo chown 1000:1000 data
cat > .env <<EOF
N8N_HOST=automate.yourbusiness.com
N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)
DB_PASSWORD=$(openssl rand -hex 20)
TZ=America/New_York
EOF
chmod 600 .env
```

Replace `automate.yourbusiness.com` with your address, and `TZ` with [your time zone](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones), for example `Europe/London`. Scheduled workflows run on this clock.

The `chown` matters: n8n runs as user 1000 inside its container, so it needs to own its data folder. **Copy `N8N_ENCRYPTION_KEY` into your password manager.** n8n uses it to encrypt the passwords and API keys you give it, so without it a restored backup can't read them.

## 2. The compose file

`compose.yaml`:

```yaml
services:
  db:
    image: postgres:17-alpine
    container_name: n8n-db
    restart: unless-stopped
    environment:
      POSTGRES_DB: n8n
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - ./db:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U n8n -d n8n"]
      interval: 5s
      retries: 10

  n8n:
    image: n8nio/n8n:stable
    container_name: n8n
    restart: unless-stopped
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: db
      DB_POSTGRESDB_DATABASE: n8n
      DB_POSTGRESDB_USER: n8n
      DB_POSTGRESDB_PASSWORD: ${DB_PASSWORD}
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: https
      N8N_PROXY_HOPS: 1
      WEBHOOK_URL: https://${N8N_HOST}/
      GENERIC_TIMEZONE: ${TZ}
      TZ: ${TZ}
      N8N_DIAGNOSTICS_ENABLED: "false"
      N8N_LISTEN_ADDRESS: 0.0.0.0
    volumes:
      - ./data:/home/node/.n8n
    depends_on:
      db:
        condition: service_healthy
    networks:
      - default
      - web

networks:
  web:
    external: true
```

Notes:

- **Postgres 17:** n8n warned us that Postgres 16 is "outside the supported range", so use 17.
- **`WEBHOOK_URL` and `N8N_PROXY_HOPS`** tell n8n that it sits behind Caddy on HTTPS, so the webhook addresses it shows you are the real public ones.
- **`N8N_LISTEN_ADDRESS: 0.0.0.0`** fixed a startup crash in our test ("n8n's address '::' is not available") on a server without IPv6. It's harmless where IPv6 works.
- **`N8N_DIAGNOSTICS_ENABLED: "false"`** turns off sending usage data to n8n.
- All your data (database and n8n's files) stays in `~/apps/n8n`, so the [backup guide](./08-backups.md) covers it.

## 3. Add it to Caddy and start it

Add this to `~/apps/caddy/Caddyfile` and reload Caddy (see the [Caddy guide](./07-caddy.md)):

```
automate.yourbusiness.com {
	reverse_proxy n8n:5678
}
```

Then start n8n:

```bash
docker compose up -d
docker compose logs -f n8n
```

Wait for the line **"Editor is now accessible"**, which took about a minute in our test, then press Ctrl+C. Until then, the page and webhooks may return errors. You can ignore messages about failing to reach `api.n8n.io` if your server blocks outgoing traffic.

## 4. Create your owner account (right away)

Open `https://automate.yourbusiness.com`. The first visitor is asked to create the **owner account**, so do it immediately, before anyone else finds the address. Use a long password from your password manager.

## 5. Your first workflow: a web form that answers back

This is the workflow we tested. It shows the basic idea: something happens (a request arrives), then n8n acts on it.

1. Click **Create workflow**, then add a **Webhook** trigger. Set **HTTP Method** to `POST` and **Path** to `new-lead`. Set **Respond** to *When Last Node Finishes*.
2. Add an **Edit Fields (Set)** node after it, and add a field called `greeting` with this value:
   `Thanks {{ $json.body.name }}, we got your message.`
3. Save, then click **Publish** at the top right. The workflow list then shows it as **Published**, which means it's live and answering.
4. Test it from your own computer:

```bash
curl -X POST https://automate.yourbusiness.com/webhook/new-lead \
  -H 'Content-Type: application/json' -d '{"name":"Ana"}'
```

You should get back `{"greeting":"Thanks Ana, we got your message."}`, and the run appears under **Executions**.

From here, replace the Set node with what you actually need: add a row to Google Sheets, send an email, or post to Slack. Each of those needs you to connect your account under **Credentials** first. We tested only the webhook flow above, not those integrations.

## Backups and updates

The [nightly backup guide](./08-backups.md) covers `~/apps/n8n`, including the database. Keep your `.env` (with the encryption key) backed up too; it lives in the same folder.

To update:

```bash
cd ~/apps/n8n
docker compose pull
docker compose up -d
```

The `stable` tag follows n8n's current stable release. Read the [release notes](https://docs.n8n.io/release-notes/) before a major version jump, and take a backup first.
